How Does External Merge Sort Sort Massive Datasets?

External merge sort is a classical sorting algorithm designed to order datasets that are too large to fit into a computer's main memory (RAM) at once. Instead of loading the entire dataset into RAM, it divides the data into smaller, manageable chunks that fit in memory, sorts each chunk individually, writes them back to disk as sorted runs, and then merges those runs together into a single sorted output. This approach minimizes slow disk input and output operations while guaranteeing an exact, completely sorted result.

Why Standard Sorting Fails on Massive Datasets

Traditional in-memory sorting algorithms like quicksort or standard merge sort assume random access to every element in RAM. When a dataset of size \(N\) exceeds the available RAM capacity \(M\) (where \(N \gg M\)), relying on virtual memory or swapping causes severe performance degradation known as thrashing, because the operating system constantly moves pages between disk and RAM.

Disk storage—whether hard disk drives (HDDs) or solid-state drives (SSDs)—is orders of magnitude slower than RAM, especially for random reads and writes. External merge sort is specifically engineered to read and write data sequentially in large blocks of size \(B\), which maximizes disk throughput and minimizes seek overhead.

Phase 1: Creating Sorted Runs

The first phase of external merge sort breaks the unsorted input file into chunks that fit comfortably within the available RAM \(M\):

  1. Read a chunk of size \(M\) from the unsorted dataset on disk into RAM.
  2. Sort the chunk in RAM using an efficient in-memory algorithm such as quicksort, timsort, or heapsort.
  3. Write the sorted chunk back to disk as a temporary file called a sorted run.
  4. Repeat this process until the entire input file has been processed.

If the total dataset has size \(N\) and RAM can hold \(M\) bytes at a time, this phase produces \(\lceil N / M \rceil\) sorted runs on disk. Each run is internally ordered, but the runs are not yet ordered relative to one another.

Phase 2: K-Way Merging

Once all sorted runs are stored on disk, the algorithm merges them into a single sorted file. Rather than merging two runs at a time, external merge sort typically performs a \(k\)-way merge to reduce the number of passes over the data.

To perform a \(k\)-way merge, the available RAM \(M\) is partitioned into \(k\) input buffers (one for each run being merged) and \(1\) output buffer, each of size \(B\) (the disk block size). The maximum number of runs that can be merged simultaneously in one pass is approximately:

\[k \approx \frac{M}{B} - 1\]

The merge proceeds as follows:

  1. Load the first block of each of the \(k\) runs into its corresponding input buffer.
  2. Use a min-heap (priority queue) of size \(k\) in RAM to track the smallest unmerged element across all \(k\) input buffers.
  3. Extract the minimum element from the min-heap and append it to the output buffer.
  4. Advance the pointer in the input buffer from which that element came. If that input buffer becomes empty, read the next block from its run on disk.
  5. Whenever the output buffer becomes full, flush it sequentially to the output file on disk.
  6. Repeat until all elements from the \(k\) runs have been written to the output.

If the number of initial runs \(\lceil N / M \rceil\) is greater than \(k\), the algorithm performs multiple merge passes. Each pass reduces the number of runs by a factor of \(k\) until only one fully sorted file remains.

I/O Complexity and Performance

The efficiency of external merge sort is measured primarily by the number of disk block transfers (I/Os) rather than CPU comparisons.

  • Initial run generation reads and writes the entire dataset once, costing \(2 \cdot (N / B)\) block transfers.
  • Each merge pass reads and writes the entire dataset once, costing \(2 \cdot (N / B)\) block transfers.
  • Number of merge passes required is \(\lceil \log_k (N / M) \rceil\).

Combining these, the total I/O complexity of external merge sort is:

\[O\left(\frac{N}{B} \log_{M/B} \frac{N}{M}\right)\]

Because \(M/B\) is typically very large (often thousands of blocks), the logarithm base is huge. In practice, even multi-terabyte datasets can often be sorted in just two or three passes over the disk.

Practical Optimizations

Real-world implementations of external merge sort, such as those used in database management systems and big data engines, often include additional optimizations:

  • Replacement selection: Instead of sorting fixed chunks of size \(M\), a priority queue in RAM continuously outputs elements to the current run while reading new elements, producing runs that average \(2M\) in size and reducing the number of merge passes.
  • Double buffering: Overlapping disk I/O with CPU processing by using background threads to prefetch the next input block and flush completed output blocks asynchronously.
  • Compression: Compressing temporary runs on disk reduces the volume of data transferred, trading a small amount of CPU time for significant I/O savings.
