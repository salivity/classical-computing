How Do AVL and Red-Black Trees Enforce Logarithmic Height?

Self-balancing binary search trees prevent the worst-case linear degradation of standard binary search trees by maintaining strict structural invariants. Both AVL trees and Red-Black trees guarantee logarithmic height relative to the number of stored nodes, ensuring that search, insertion, and deletion operations run in worst-case logarithmic time. They achieve this balance using local restructuring operations called tree rotations, which preserve the in-order traversal property while adjusting subtree heights.

Why Standard Binary Search Trees Degrade

In a standard binary search tree with \(n\) nodes, inserting elements in sorted or nearly sorted order produces a skewed tree that resembles a linked list. In this worst-case scenario, the height \(h\) grows linearly, meaning \(h = \Theta(n)\), and fundamental operations degrade to \(O(n)\) time. To guarantee \(O(\log n)\) performance, a tree must bound its height \(h\) by \(c \log_2(n)\) for some small constant \(c\) after every modification.

Tree Rotations as Height-Preserving Primitives

A tree rotation is a constant-time \(O(1)\) local pointer manipulation that changes the parent-child relationship between two adjacent nodes while preserving the binary search tree property.

For a right rotation around a node \(y\) with left child \(x\):

  • \(x\) becomes the new root of the subtree.
  • \(y\) becomes the right child of \(x\).
  • The original right subtree of \(x\) becomes the left subtree of \(y\).

A left rotation performs the exact symmetric operation. Because rotations only update a fixed number of pointers, they allow a tree to shift height from a taller subtree to a shorter one without violating the key ordering.

How AVL Trees Enforce Balance

AVL trees, named after Adelson-Velsky and Landis, enforce a strict height-based invariant. For every node in the tree, the balance factor—defined as the height of the left subtree minus the height of the right subtree—must be \(-1\), \(0\), or \(1\).

If an insertion or deletion causes a node's balance factor to reach \(-2\) or \(+2\), the tree is rebalanced using one of four rotation cases:

  • Left-Left (LL) and Right-Right (RR) cases: Resolved with a single right or left rotation.
  • Left-Right (LR) and Right-Left (RL) cases: Resolved with a double rotation (a left rotation followed by a right rotation, or vice versa).

By maintaining this balance factor invariant, an AVL tree with \(n\) nodes has a minimum number of nodes \(N(h)\) for height \(h\) governed by the Fibonacci-like recurrence \(N(h) = 1 + N(h-1) + N(h-2)\). This yields a strict upper bound on height:

\[h < 1.44 \log_2(n + 2) - 0.328\]

How Red-Black Trees Enforce Balance

Red-Black trees enforce a more relaxed, color-based invariant rather than tracking exact heights. Every node is colored either red or black, and the tree must satisfy five properties:

  1. Every node is either red or black.
  2. The root is black.
  3. Every leaf (null pointer) is black.
  4. If a node is red, both of its children are black (no two consecutive red nodes).
  5. For each node, all simple paths from the node to descendant leaves contain the same number of black nodes, known as the black-height \(bh\).

When an insertion or deletion violates property 4 or property 5, the tree restores balance using a combination of recoloring and at most two rotations for insertion (or three for deletion). Because no path can have two consecutive red nodes, the longest possible path from the root to a leaf is at most twice the length of the shortest path (which consists entirely of black nodes). Since a tree with black-height \(bh\) has at least \(2^{bh} - 1\) internal nodes, the total height \(h\) is bounded by:

\[h \le 2 \log_2(n + 1)\]

Comparing the Two Approaches

Both data structures achieve \(O(\log n)\) worst-case height, but they trade off strictness of balance against maintenance overhead. AVL trees maintain tighter height bounds (\(1.44 \log_2 n\) versus \(2 \log_2 n\)), which makes lookups slightly faster on average. Red-Black trees permit greater height imbalance, which reduces the number of rotations required during insertions and deletions, making them preferable for write-heavy workloads.
