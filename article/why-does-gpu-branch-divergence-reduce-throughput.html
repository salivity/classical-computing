Why Does GPU Branch Divergence Reduce Throughput?

Branch divergence occurs in graphics processing units when threads within the same execution group take different paths at a conditional statement. Because modern GPUs execute threads in lockstep using a single instruction stream per group, divergent paths cannot run simultaneously. Instead, the hardware serializes each path and disables inactive threads, which increases total execution time and lowers overall computational throughput.

The SIMT Execution Model

GPUs achieve high throughput by grouping threads into fixed-size batches called warps (typically 32 threads on NVIDIA architectures) or wavefronts (typically 64 threads on AMD architectures). These groups operate under the Single Instruction, Multiple Threads (SIMT) model.

In an SIMT architecture, a single instruction fetch and decode unit drives all threads in the warp or wavefront. Every thread in the group executes the same instruction at the same time, but each operates on its own private registers and data. This design minimizes control-logic overhead and maximizes the chip area dedicated to arithmetic logic units (ALUs).

How Branch Divergence Serializes Paths

When a warp encounters a conditional branch, such as an if-else statement, all threads evaluate the branch condition. If every thread evaluates the condition to the same outcome, no divergence occurs, and the warp proceeds at full efficiency.

If some threads evaluate the condition as true and others as false, branch divergence occurs. Because the warp shares a single instruction stream, it cannot fetch and execute both the if block and the else block simultaneously. To handle this, the hardware uses an active mask—a bitmask with one bit per thread—to track which threads are enabled:

  1. The warp sets the active mask to enable only the threads taking the if path and executes those instructions while the remaining threads sit idle.
  2. Once the if path finishes, the warp flips the active mask to enable only the threads taking the else path and executes those instructions.
  3. After both paths complete, the threads reconverge at the instruction following the conditional block, and the active mask is restored.

Impact on Execution Time and Throughput

Serializing divergent paths directly increases latency and reduces hardware utilization. If the if branch takes time \(T_{\text{if}}\) and the else branch takes time \(T_{\text{else}}\), a non-divergent warp would only spend \(\max(T_{\text{if}}, T_{\text{else}})\) time. Under branch divergence, the total execution time becomes:

\[T_{\text{divergent}} = T_{\text{if}} + T_{\text{else}}\]

During each serialized phase, only a fraction of the warp's lanes perform useful work. If \(k\) out of \(N\) threads take the if path and \(N - k\) threads take the else path, the average lane utilization \(U\) across the divergent region drops below \(100\%\):

\[U = \frac{k \cdot T_{\text{if}} + (N - k) \cdot T_{\text{else}}}{N \cdot (T_{\text{if}} + T_{\text{else}})}\]

In the worst case—such as a 32-way switch statement where each thread in a warp takes a unique path—the warp executes 32 separate passes with only one active thread per pass, reducing effective throughput by a factor of \(32\).

Mitigating Branch Divergence

Developers reduce branch divergence by structuring algorithms so that threads within the same warp follow the same control flow. Common techniques include sorting data by branch outcome before launching a kernel, replacing simple conditionals with branchless arithmetic or predicated instructions, and aligning data structures to warp boundaries.
