How Does a Bloom Filter Test Set Membership?

A Bloom filter is a space-efficient probabilistic data structure used in classical computing to test whether an element is a member of a set. It combines a fixed-size bit array with multiple independent hash functions to achieve fast insertions and lookups. While it can occasionally produce false positives by indicating that an element might be in the set when it is not, it guarantees zero false negatives, meaning it will never falsely claim that an inserted element is absent.

The Bit Array and Hash Functions

A Bloom filter consists of a bit array of \(m\) bits, all initially set to \(0\), and \(k\) independent hash functions \(h_1, h_2, \dots, h_k\). Each hash function maps an input element \(x\) to a uniform random index in the range \(\{0, 1, \dots, m - 1\}\).

Because the bit array stores only single bits rather than the actual elements, the data structure requires significantly less memory than a hash table or a balanced search tree.

Inserting an Element

To insert an element \(x\) into the Bloom filter, the algorithm computes all \(k\) hash values:

\[h_1(x), h_2(x), \dots, h_k(x)\]

Each resulting index in the bit array is then set to \(1\). If a bit at a given index is already \(1\) due to a previous insertion, it simply remains \(1\). Both the time complexity of insertion and the number of bit operations required are \(O(k)\), independent of the number of elements already stored.

Querying for Membership

To test whether an element \(y\) is in the set, the algorithm computes the same \(k\) hash functions for \(y\) and checks the corresponding positions in the bit array:

  • If any of the bits at indices \(h_1(y), h_2(y), \dots, h_k(y)\) is \(0\), the element \(y\) is definitely not in the set.
  • If all of the bits at those indices are \(1\), the element \(y\) is probably in the set.

Why Zero False Negatives Are Guaranteed

A false negative would occur if an element \(x\) was previously inserted, yet a subsequent query for \(x\) returned that it is not in the set. In a standard Bloom filter, this is impossible because bits are only ever changed from \(0\) to \(1\) during insertions, never from \(1\) to \(0\).

Once \(x\) is inserted, all \(k\) positions \(h_1(x), \dots, h_k(x)\) are set to \(1\) and remain \(1\) permanently. Therefore, any future query for \(x\) will always find all \(k\) bits set to \(1\), guaranteeing a zero false-negative rate.

Understanding False Positives

False positives happen because multiple elements share the same \(m\)-bit array. Even if an element \(y\) was never inserted, its \(k\) hash positions might all have been set to \(1\) by various combinations of other inserted elements.

After inserting \(n\) elements into a bit array of size \(m\) using \(k\) hash functions, the probability \(p\) of a false positive is approximately:

\[p \approx \left(1 - e^{-kn / m}\right)^k\]

For a given \(m\) and \(n\), the number of hash functions \(k\) that minimizes the false-positive rate is:

\[k = \frac{m}{n} \ln 2\]

By tuning \(m\) and \(k\) according to the expected number of elements \(n\), developers can trade a small, controlled false-positive rate for substantial memory savings and constant-time \(O(k)\) lookups.
