Why Are L1 Caches Split While L2 and L3 Are Unified?

Modern processors use a split Level 1 cache with separate instruction and data caches while keeping Level 2 and Level 3 caches unified to balance execution speed against capacity efficiency. At the core pipeline boundary, instructions and data are accessed simultaneously with very different patterns, making separation essential to avoid bottlenecks. Deeper in the memory hierarchy, workloads vary widely in how much instruction versus data space they need, so a unified design lets the processor share cache capacity dynamically and simplify coherence.

Why L1 Caches Are Split

The primary reason for splitting the L1 cache into an instruction cache (L1i) and a data cache (L1d) is to eliminate structural hazards in the CPU pipeline. In a pipelined processor, the instruction fetch stage needs to read the next instruction on every clock cycle, while the memory access stage may simultaneously need to read or write data for an earlier instruction. If L1 were a single unified cache, both stages would compete for the same cache ports, forcing the pipeline to stall unless expensive multi-ported memory arrays were used.

Splitting L1 also allows each cache to be tailored to its specific access pattern:

  • Instruction cache (L1i): Instructions are mostly read-only during normal execution and are typically fetched sequentially or in predictable branch targets. Because the CPU rarely writes to L1i, it does not need write-back hardware or complex dirty-bit tracking, and it can include instruction-specific optimizations such as pre-decoded bits.
  • Data cache (L1d): Data accesses involve both reads and writes, often with less predictable addresses. L1d must support fast store buffers, write-back or write-through policies, and byte-level or word-level masking.

Why L2 and L3 Caches Are Unified

Once requests miss the L1 caches and move to L2 or L3, the immediate pressure of single-cycle pipeline port contention disappears. At these levels, latency is higher and accesses are less frequent, so a unified cache can serve both instruction and data misses without causing the same pipeline bottleneck.

A unified design offers several major advantages at L2 and L3:

  • Dynamic capacity sharing: Different programs have very different working sets. A tight numerical loop might need almost no instruction space and a large amount of data space, whereas a large application with complex control flow might have a huge instruction footprint. A unified cache automatically allocates space to whichever type of information needs it most.
  • Simpler cache coherence: In multi-core processors, keeping caches consistent across cores requires tracking which core holds which cache lines. Having a single unified L2 and L3 structure avoids duplicating coherence tracking for separate instruction and data hierarchies, and it makes handling self-modifying code or just-in-time compilation much simpler.
  • Better area and power efficiency: Maintaining one larger, unified tag and data array reduces control logic overhead compared to managing two separate caches at every level.

Balancing Speed and Flexibility

The split-L1, unified-L2/L3 hierarchy is a practical compromise between two classic computer architecture models. At the fastest level closest to the execution units, the processor behaves like a modified Harvard architecture to maximize bandwidth and prevent pipeline stalls. Deeper in the hierarchy, it reverts to a unified Von Neumann view so that expensive silicon area is used as efficiently as possible across diverse workloads.
