How Do Big-Endian and Little-Endian Byte Orders Differ?

Big-endian and little-endian byte ordering are two opposite ways of arranging the individual bytes of a multi-byte word in computer memory. Big-endian places the most significant byte at the lowest memory address, while little-endian places the least significant byte at the lowest memory address. Both formats store the exact same numerical value, and the difference lies solely in the sequence in which those bytes are laid out across consecutive memory locations.

Understanding Multi-Byte Words and Memory Addressing

In classical computing, memory is typically byte-addressable, meaning each unique memory address points to a single 8-bit byte. However, processors routinely work with larger data types—such as 16-bit, 32-bit, or 64-bit integers—that span multiple consecutive bytes.

For a \(k\)-byte word, the value is composed of bytes ordered from the most significant byte (MSB), which carries the highest place value, down to the least significant byte (LSB), which carries the lowest place value. Consider a 32-bit (4-byte) hexadecimal value:

\[\text{0x12345678}\]

Here, \(\text{0x12}\) is the most significant byte, and \(\text{0x78}\) is the least significant byte. When this word is stored starting at memory address \(A\), it occupies addresses \(A\), \(A+1\), \(A+2\), and \(A+3\).

Big-Endian Byte Ordering

In big-endian systems, the most significant byte is stored first, at the lowest memory address (\(A\)), and the remaining bytes follow in decreasing order of significance. Using the 32-bit example \(\text{0x12345678}\):

  • Address \(A\): \(\text{0x12}\) (MSB)
  • Address \(A+1\): \(\text{0x34}\)
  • Address \(A+2\): \(\text{0x56}\)
  • Address \(A+3\): \(\text{0x78}\) (LSB)

This order matches how numbers are conventionally written in Western notation, where the largest place value appears on the left and the smallest appears on the right. Big-endian is the standard for network protocols (often called network byte order) and is historically associated with architectures such as Motorola 68000 and SPARC.

Little-Endian Byte Ordering

In little-endian systems, the least significant byte is stored first, at the lowest memory address (\(A\)), and the remaining bytes follow in increasing order of significance. Using the same 32-bit example \(\text{0x12345678}\):

  • Address \(A\): \(\text{0x78}\) (LSB)
  • Address \(A+1\): \(\text{0x56}\)
  • Address \(A+2\): \(\text{0x34}\)
  • Address \(A+3\): \(\text{0x12}\) (MSB)

Notice that the bits within each individual byte remain in their normal order; only the arrangement of the bytes themselves is reversed. Little-endian is the dominant format in modern consumer hardware, including x86 and x86-64 processors, and is the default mode for most ARM-based devices.

Practical Implications

Because single-byte values (such as ASCII characters) occupy only one byte, endianness does not affect them. However, endianness becomes critical whenever multi-byte data is shared between systems, written to binary files, or transmitted over a network.

If a little-endian machine writes a 32-bit integer directly to a file and a big-endian machine reads those raw bytes without converting them, the value \(\text{0x12345678}\) will be interpreted as \(\text{0x78563412}\). To prevent this data corruption, software and network protocols explicitly define a standard byte order and perform byte-swapping operations whenever a host's native endianness differs from the standard.
