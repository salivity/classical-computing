How Does Binary Search Reduce Lookup Time?

Binary search reduces lookup time in a sorted array to logarithmic complexity by repeatedly dividing the search interval in half. Instead of checking every element one by one, the algorithm compares the target value to the middle element of the current range and eliminates half of the remaining elements at each step. This divide-and-conquer strategy allows classical computers to locate an item in very large datasets using only a small number of comparisons.

The Requirement of a Sorted Array

In an unsorted array, there is no predictable relationship between an element's value and its position. Finding a specific value requires a linear search, which inspects elements sequentially from start to finish and takes \(O(n)\) time in the worst case for an array of \(n\) elements.

When an array is sorted in ascending or descending order, the ordering provides structural information. If a value at index \(m\) is smaller than the target value, every element at an index less than \(m\) is also guaranteed to be smaller than the target. This property makes it safe to discard entire sections of the array without examining them.

How the Divide-and-Conquer Process Works

Binary search maintains two pointers, low and high, representing the inclusive bounds of the current search interval. Initially, low = 0 and high = n - 1.

At each step, the algorithm performs the following operations:

  1. Compute the middle index: \(m = \lfloor (\text{low} + \text{high}) / 2 \rfloor\).
  2. Compare the middle element \(A[m]\) with the target \(T\).
  3. If \(A[m] = T\), the search succeeds and returns \(m\).
  4. If \(A[m] < T\), the target cannot be in the left half, so update \(\text{low} = m + 1\).
  5. If \(A[m] > T\), the target cannot be in the right half, so update \(\text{high} = m - 1\).

This loop continues until the target is found or \(\text{low} > \text{high}\), which indicates that the target is not in the array.

Deriving the Logarithmic Complexity

Because each comparison cuts the remaining search space in half, the size of the interval shrinks exponentially with each step. Starting with \(n\) elements:

  • After 1 comparison, at most \(n / 2\) elements remain.
  • After 2 comparisons, at most \(n / 4\) elements remain.
  • After \(k\) comparisons, at most \(n / 2^k\) elements remain.

In the worst case, the search terminates when the interval is reduced to \(1\) element:

\[\frac{n}{2^k} = 1 \implies n = 2^k\]

Taking the base-2 logarithm of both sides gives the maximum number of steps \(k\):

\[k = \log_2(n)\]

Thus, the worst-case and average-case time complexity of binary search is \(O(\log n)\). The best-case complexity is \(O(1)\), which occurs when the middle element on the first comparison matches the target.

Practical Impact in Classical Computing

In classical computing, where memory access and comparisons are performed sequentially on a single processor, \(O(\log n)\) scaling is dramatically faster than \(O(n)\) scaling. For an array containing \(1,000,000\) elements, linear search may require up to \(1,000,000\) comparisons, whereas binary search requires at most \(\lceil \log_2(1,000,000) \rceil = 20\) comparisons. Even if the dataset grows to \(1,000,000,000\) elements, binary search needs at most \(30\) comparisons.
